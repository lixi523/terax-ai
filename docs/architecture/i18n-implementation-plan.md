# i18n Implementation Plan

> Multi-language support design and staged rollout for Terax.
> Target: replace all hardcoded UI strings with `t('key')` calls, enable runtime language switching.

## 1. Scope & Goals

| Goal | Status | Notes |
|------|--------|-------|
| Runtime language switch (no restart) | Planned | Via `i18next.changeLanguage()` |
| Type-safe translation keys | Planned | `i18next-typescript` generates types |
| Initial languages: English (source), Simplified Chinese | Planned | zh-CN as first target |
| Extensible for community contributions | Planned | Crowdin/Weblate ready structure |
| Zero hardcoded **user-visible** strings in `.tsx` | Planned | Including `title`, `placeholder`, `aria-label`; **excludes technical terms, provider names, theme names** |
| CI gate preventing regressions | Planned | `pnpm i18n:check` in CI |

**Non-goals (v1):**
- RTL layout support (Arabic, Hebrew)
- Pluralization rules beyond basic ICU
- Date/number formatting per locale (use browser defaults)
- Translation of terminal output / shell messages
- AI-generated content translation
- Tauri native dialogs (file chooser, message boxes)
- **Translation of technical terms, AI provider names, editor theme names, keyboard shortcut hints** (marked `non-translatable`)

---

## 2. Technology Choices

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Runtime | `i18next` + `react-i18next` | Mature, tree-shakable, TypeScript-first |
| Type safety | `i18next-typescript` | Generates `t` function with key autocomplete |
| Language detection | Custom detector | Tauri store → localStorage → navigator → en |
| Persistence | Tauri store (`@tauri-apps/plugin-store`) | Survives restart, synced with settings |
| Extraction | Babel AST scanner (custom) | Handles JSX text, `title`, `placeholder`, `aria-label` |
| Validation | Custom script | CI check for missing keys |

**Bundle impact:**
| Component | Size (gzipped) |
|-----------|----------------|
| i18next core | ~5 kB |
| react-i18next | ~3 kB |
| Language detector | ~2 kB |
| en.json (initial) | ~15 kB |
| zh-CN.json (lazy) | ~20 kB |
| **Total initial** | **~25 kB** |
| **Total with zh-CN** | **~45 kB** |

> **Note**: Bundle budget impact is acceptable (~0.5% of 7-8 MB target). Non-English locales loaded on demand.

## 3. Architecture

```
src/
├── i18n/
│   ├── index.ts                 # i18next init, exports `t`, `useTranslation`
│   ├── resources/
│   │   ├── en.json              # Source of truth (all keys, inlined)
│   │   └── zh-CN.json           # Translated (lazy loaded)
│   ├── types.ts                 # Generated by i18next-typescript
│   ├── detector.ts              # Custom detector (settings store → localStorage → navigator)
│   └── utils.ts                 # Helpers: `tRaw`, `namespace`, etc.
├── modules/
│   ├── settings/
│   │   └── sections/            # Language selector UI
│   │       └── GeneralSection.tsx
│   └── header/
│       └── SearchInline.tsx     # Example migration target
└── components/                  # All components import `t` from '@/i18n'
```

**Initialization order (critical):**
```
1. main.tsx loads
2. Tauri async setup: `await invoke("pty_close_all")`, `await initLaunchDir()`
3. i18n.init() called SYNCHRONOUSLY (after Tauri setup, before any render)
4. ReactDOM.createRoot().render(<App />)
5. App reads persisted locale from settings store or detector
```

> **Constraint**: Existing `main.tsx` has mandatory async Tauri calls (lines 23-26). i18n **must initialize after them** but **before React render** to avoid FOUC.

**Lazy loading strategy:**
```ts
// src/i18n/index.ts
import { enJson } from './resources/en.json';

const resources = {
  en: { translation: enJson },           // Inlined at build time
  'zh-CN': {                           // Lazy loaded on demand
    translation: () => import('./resources/zh-CN.json'),
  },
};
```

**Locale persistence:** Reuse existing settings `LazyStore` from `src/modules/settings/store.ts`:
```ts
// In store.ts, add to defaults:
locale: 'system' as 'system' | 'en' | 'zh-CN',

// In GeneralSection.tsx:
const { locale, setLocale } = useSettingsStore(); // Same store as other settings
```
No new store needed — persists alongside theme, editor prefs, etc.

## 4. Translation Key Convention

```
<feature>.<section>.<element>[.<variant>]
```

| Example | Meaning |
|---------|---------|
| `settings.general.language.label` | Label for language dropdown |
| `settings.general.language.option.system` | "System" option |
| `terminal.tab.closeConfirm.many` | "Close {count} tabs?" |
| `ai.composer.placeholder` | Composer input placeholder |
| `commandPalette.search.placeholder` | "Search commands..." |
| `common.actions.save` | Reusable "Save" |
| `common.actions.cancel` | Reusable "Cancel" |
| `header.search.placeholder` | "Search (⌘K)" |

**Rules:**
- Lowercase, dot-separated, kebab-case segments
- Group by feature/module, not by page
- Reuse `common.*` for shared verbs/nouns
- Interpolation: `t('key', { count: 3 })` → `{count}` in JSON
- No HTML in values (use components for rich text)
- Keep keys stable: don't rename without updating all locales

### String Categories

1. **UI Labels** (button text, menu items, tooltips) - ~1,200 translatable
2. **Placeholders** (input hints) - ~50
3. **ARIA labels** (accessibility) - ~70
4. **Status messages** (loading, error, empty states) - ~150

6. **Theme names** (Kanagawa, Dracula, etc.) - **non-translatable**

## 8. Migration Tooling

### 8.1 Extraction Script

```bash
# scripts/i18n-extract.ts
// Uses Babel AST to scan .tsx files
// Finds:
//   - JSX text children: <span>Search</span>
//   - title props: <Button title="Close" />
//   - placeholder props: <Input placeholder="Search..." />
//   - aria-label props: <button aria-label="Close" />
// Outputs CSV for manual review → merge into en.json
```

**Usage:**
```bash
pnpm i18n:extract --module header   # Extract only header module
pnpm i18n:extract --all             # Extract all modules
```

### 8.2 Validation Script (CI)

```bash
# scripts/i18n-validate.ts
// - Load all locale JSONs
// - Ensure same key set across locales
// - Warn on unused keys (not referenced in code)
// - Error on missing interpolations
```

**CI integration:**
```yaml
# .github/workflows/i18n-check.yml
jobs:
  i18n-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pnpm i18n:check
```

### 8.3 Dev Helper

```ts
// src/i18n/utils.ts
export function tRaw(key: string, opts?: TOptions): string {
  return i18n.t(key, opts);
}

export function namespace(ns: string) {
  return (key: string, opts?) => t(`${ns}.${key}`, opts);
}

// Usage in component:
const t = namespace('settings.editor');
<button>{t('fontSize')}</button>
```

## 9. TypeScript Integration

```json
// package.json
{
  "scripts": {
    "i18n:types": "i18next-typescript --input src/i18n/resources/en.json --output src/i18n/types.d.ts",
    "i18n:check": "ts-node scripts/i18n-validate.ts",
    "i18n:extract": "ts-node scripts/i18n-extract.ts"
  }
}
```

Generated `types.d.ts`:
```ts
declare module 'i18next' {
  interface CustomTypeOptions {
    returnNull: false;
    resources: {
      common: { actions: { save: string; cancel: string } };
      settings: { general: { language: { label: string } } };
      // ...
    };
  }
}
```

Now `t('settings.general.language.label')` is fully typed with autocomplete.

## 10. Language Selector UX

**Location:** Settings → General → Language

```tsx
// src/modules/settings/sections/GeneralSection.tsx
import { useSettingsStore } from '@/modules/settings/store';
const { t } = useTranslation();
const { locale, setLocale } = useSettingsStore(); // Reuses existing LazyStore

<SettingRow title={t('settings.general.language.label')}>
  <Select value={locale} onValueChange={setLocale}>
    <SelectItem value="system">{t('settings.general.language.option.system')}</SelectItem>
    <SelectItem value="en">{t('settings.general.language.option.en')}</SelectItem>
    <SelectItem value="zh-CN">{t('settings.general.language.option.zh-CN')}</SelectItem>
  </Select>
</SettingRow>
```

**Behavior:**
- `system` → follows OS locale (via detector), updates live
- Explicit choice → persists to **existing settings LazyStore**, overrides system
- Change takes effect immediately via `i18next.changeLanguage()`

## 11. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| String count > 5000 | Long tail migration | Phase by module, parallelize |
| Dynamic strings (template literals) | Missed keys | ESLint rule: `no-restricted-syntax` for template literals with interpolation in JSX |
| Third-party libs (toast, dialog) | Untranslated | Wrap lib calls with `t()` |
| Tauri native menus/dialogs | Out of scope v1 | Document limitation; later use `tauri-plugin-i18n` |
| Translation drift | Stale zh-CN | CI check + `i18n:extract` finds new keys |
| Bundle size bloat | +45 kB total | Acceptable; lazy-load non-default locales |
| Runtime performance | Extra function call | i18next caches translations; negligible overhead |

## 15. Architecture Decision Records (ADRs)

### ADR-001: i18n Initialization Order
- **Decision**: `i18n.init()` runs AFTER Tauri async setup (`invoke("pty_close_all")`, `initLaunchDir()`) but BEFORE `ReactDOM.createRoot().render()`
- **Reason**: Existing `main.tsx` has mandatory async calls that cannot be moved; i18n must be ready before first paint to avoid FOUC
- **Status**: Accepted

### ADR-002: Locale Persistence
- **Decision**: Reuse existing settings `LazyStore` (`src/modules/settings/store.ts`); add `locale` field to defaults
- **Reason**: Avoids new store, single source of truth, survives restart, synced with other preferences
- **Status**: Accepted

### ADR-003: Translation Scope
- **Decision**: Translate only user-facing UI copy (labels, placeholders, status, ARIA). **Do NOT translate**: AI provider names (OpenAI, Anthropic...), editor theme names (Kanagawa, Dracula...), technical terms (PTY, WebGPU, LSP...), keyboard shortcut hints (⌘K)
- **Reason**: Brand/technical accuracy, reduces translation burden (~70% strings excluded), avoids zh-CN contamination of English terminology
- **Implementation**: Mark excluded keys in `en.json` under `"__nonTranslatable": [...]` array; extraction script skips them
- **Status**: Accepted
